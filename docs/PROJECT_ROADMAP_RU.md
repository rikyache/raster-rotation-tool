# Полная шпаргалка по проекту Raster Rotation Tool

Документ рассчитан на человека, который только начинает разбираться в C# и WPF. Номера строк указаны для текущей версии проекта. После редактирования файлов они могут немного сдвинуться, поэтому рядом всегда указаны имена классов и методов, по которым удобно искать через `Ctrl+F`.

## 1. Что делает проект

Это настольное Windows-приложение для работы с растровыми изображениями. Оно умеет:

- открыть изображение из окна выбора файла или получить путь при запуске;
- показать изображение, его размер, DPI, формат и текущий угол;
- обрезать прямоугольную область мышью;
- отразить изображение по горизонтали или вертикали;
- повернуть на `-90`, `+90`, `180` градусов или на произвольный угол;
- показать сетку поверх изображения;
- сохранить результат в исходном графическом формате;
- запомнить тему, фон, сетку и качество JPEG;
- выполнить основные операции из командной строки.

## 2. Общая архитектура

Решение разделено на три проекта:

```text
RasterRotation.sln
|
+-- RasterRotation.Core    общая логика и объектная модель
|
+-- RasterRotation.Wpf     графическое приложение Windows
|
+-- RasterRotation.Cli     консольное приложение
```

Главная идея архитектуры: интерфейс пользователя не должен сам выполнять математические преобразования пикселей. WPF и CLI принимают команды пользователя, а работу с изображением передают библиотеке `RasterRotation.Core`.

Зависимости направлены так:

```text
RasterRotation.Wpf ----\
                       >---- RasterRotation.Core
RasterRotation.Cli ----/
```

`Core` ничего не знает о кнопках конкретного окна или аргументах консоли. Поэтому его классы можно повторно использовать в другом интерфейсе, например WinForms или Avalonia.

## 3. Где находится точка входа

У проекта две точки входа, потому что есть два запускаемых приложения.

### Графическое приложение WPF

Формальная точка запуска WPF создаётся платформой автоматически на основе `App.xaml`. Логическая точка входа, написанная в проекте, находится здесь:

- `src/RasterRotation.Wpf/App.xaml`, строки 1-4: объявляет класс приложения и связывает событие запуска с методом `OnStartup`;
- `src/RasterRotation.Wpf/App.xaml.cs`, строки 8-13: метод `OnStartup`.

Порядок запуска:

1. .NET запускает WPF-приложение.
2. `App.xaml` указывает `Startup="OnStartup"`.
3. `OnStartup` ищет среди аргументов командной строки путь к существующему файлу.
4. Создаётся `new MainWindow(initialFile)`.
5. Вызывается `window.Show()`, и главное окно появляется на экране.

Ключевой код:

```csharp
var initialFile = e.Args.FirstOrDefault(...);
var window = new MainWindow(initialFile);
window.Show();
```

### Консольное приложение

Точка входа CLI находится в `src/RasterRotation.Cli/Program.cs`, строка 13:

```csharp
public static int Main(string[] args)
```

`args` — массив параметров командной строки. Возвращаемое число — код завершения программы:

- `0` — успех;
- `1` — ошибка обработки;
- `2` — не передан обязательный путь к файлу.

## 5. Как выполняются основные сценарии

### Открытие изображения в GUI

```text
Кнопка «Открыть» в MainWindow.xaml
-> OpenClick() в MainWindow.xaml.cs
-> LoadImage()
-> IImageFileService.Load()
-> WicImageFileService.Load()
-> создаётся ImageDocument
-> UpdatePreview()
-> BitmapSource показывается в PreviewImage
```

### Поворот на 90 градусов

```text
Кнопка «+90»
-> RotateRightClick()
-> RotateRightAngle(90)
-> WicImageTransformer.RotateRightAngle()
-> ImageDocument.ReplaceBitmap()
-> событие Changed
-> UpdatePreview() и UpdateStatus()
```

### Свободное вращение

```text
Пользователь вводит угол
-> ApplyFreeRotationClick()
-> угол прибавляется к суммарному углу текущей серии
-> результат заново строится от базовой картинки серии
-> WicImageTransformer.RotateFree()
-> вычисляются размеры нового холста
-> изображение рисуется с RotateTransform
-> результат помещается в ImageDocument
```

Пересчёт от базовой картинки нужен, чтобы пустые углы уже повёрнутого холста не вращались повторно. Без этого холст увеличивался бы после каждого применения, а полезная часть изображения визуально становилась бы всё меньше. Обрезка, отражение, поворот на 90 градусов или открытие нового файла начинают новую серию свободного вращения.

### Обрезка мышью

```text
Включение режима «Обрезка»
-> MouseLeftButtonDown запоминает первую точку
-> MouseMove рисует прямоугольник
-> MouseLeftButtonUp завершает выделение
-> ConvertUiRectToBitmapRegion() переводит координаты окна в пиксели
-> WicImageTransformer.Crop()
-> результат показывается в окне
```

Перевод координат нужен потому, что картинка может быть уменьшена для показа. Например, выделение шириной 300 экранных точек может соответствовать 1200 пикселям исходного файла.

### Сохранение

```text
Кнопка «Сохранить»
-> SaveClick()
-> SaveImage()
-> EnsureOriginalExtension()
-> WicImageFileService.Save()
-> CreateEncoder()
-> выбранный WIC-кодировщик записывает файл
```

### Выполнение CLI

```text
Program.Main(args)
-> CliOptions.Parse(args)
-> WicImageFileService.Load()
-> List<ImageOperation>
-> operation.Apply() для каждой операции
-> Save()
-> WicImageFileService.Save()
```

## 6. Минимальный словарь C# для понимания проекта

### `class`

Класс — описание объекта с данными и поведением. Например, `ImageDocument` хранит изображение и умеет заменить его после операции.

### `interface`

Интерфейс — договор без конкретной реализации. `IImageTransformer` говорит, что обработчик обязан иметь методы `Crop`, `FlipHorizontal` и другие. `WicImageTransformer` выполняет этот договор.

### `public`, `private`, `internal`, `protected`

- `public` — доступно другим классам и проектам;
- `private` — доступно только внутри текущего класса;
- `internal` — доступно внутри текущего проекта;
- `protected` — доступно классу и его наследникам.

### Свойство

```csharp
public int Width { get; }
```

Это свойство только для чтения. Внешний код может узнать ширину, но не может произвольно её изменить.

### Метод

```csharp
public BitmapSource Crop(BitmapSource source, CropRegion region)
```

Метод получает исходное изображение и область, затем возвращает новое изображение.

### Конструктор

Метод с именем класса, вызываемый через `new`. Он подготавливает новый объект.

```csharp
var window = new MainWindow(initialFile);
```

### Событие

```csharp
public event EventHandler? Changed;
```

Событие позволяет объекту сообщить подписчикам об изменении.

### Наследование и полиморфизм

`CropOperation`, `FlipOperation` и `RotateOperation` наследуются от `ImageOperation`. Поэтому разные операции можно хранить в одной коллекции и вызывать одинаково.

### `record struct`

Компактный тип данных со сравнением по значениям. `CropRegion` удобно хранит четыре числа области обрезки.

### `enum`

Перечисление фиксированных вариантов. `FlipDirection` допускает только `Horizontal` или `Vertical`.

### `nullable` и знак `?`

```csharp
private ImageDocument? _document;
```

Знак `?` означает, что переменная может временно содержать `null`, например пока файл ещё не открыт.

### `var`

Компилятор сам выводит тип по правой части. Тип всё равно остаётся строгим и известным при компиляции.

### Лямбда `=>`

Короткая функция. Например:

```csharp
bitmap => _transformer.FlipHorizontal(bitmap)
```

Она принимает `bitmap` и возвращает его отражённую версию.

### `try` / `catch`

Перехват ошибок. Если файл нельзя открыть или сохранить, приложение показывает сообщение вместо аварийного завершения.

## 8. За что отвечают графические форматы

### PNG (`.png`)

Сжатие без потерь, поддержка прозрачности. Хорош для интерфейсов, схем, скриншотов и изображений с резкими границами. Повторное сохранение не создаёт JPEG-подобных артефактов, но фотографии могут занимать больше места.

### JPEG (`.jpg`, `.jpeg`, `.jfif`)

Сжатие с потерями. Хорош для фотографий и небольшого размера файла, но не поддерживает обычную прозрачность. При повторных сохранениях качество может снижаться. В проекте качество задаётся числом от 1 до 100, по умолчанию 92. Точное исходное качество JPEG невозможно надёжно восстановить из уже сжатого файла.

### TIFF (`.tif`, `.tiff`)

Контейнер высокого качества, распространён в сканировании, печати и архивировании. Может использовать разные виды сжатия и хранить несколько страниц/кадров. Текущая реализация загружает и сохраняет первый кадр.

### BMP (`.bmp`)

Простой Windows-формат, обычно без эффективного сжатия. Легко декодируется, но файлы часто большие.

### GIF (`.gif`)

Формат с палитрой до 256 цветов, поддерживает прозрачность и анимацию. Текущая программа работает с первым кадром, поэтому полноценное сохранение анимации не реализовано.

### HEIF/HEIC (`.heif`, `.heic`)

Современный формат с эффективным сжатием, часто используется телефонами. Поддержка зависит от установленных в Windows WIC-расширений. Система может уметь читать HEIF, но не иметь доступного кодировщика для записи; тогда сохранение в исходном формате завершится понятной ошибкой.

### WebP (`.webp`)

Современный формат для веба, поддерживает сжатие с потерями, без потерь, прозрачность и анимацию. В диалоге открытия он указан, но фактическая поддержка зависит от WIC-кодека в Windows. Встроенного явного `WebPBitmapEncoder` в текущем коде нет.

### WDP/JXR (`.wdp`, `.jxr`)

Windows Media Photo / JPEG XR. Поддерживается в коде через `WmpBitmapEncoder`; рассчитан на качественные изображения и расширенный диапазон значений.

Важно: фраза «сохранить в том же формате» означает сохранение тем же типом контейнера и расширением. Она не означает побитовое совпадение с оригиналом: после обрезки или вращения пиксели и служебные данные неизбежно меняются. Часть расширенных метаданных, многокадровость и точные параметры исходного кодировщика текущая версия не переносит.

## 10. Как собрать, запустить и проверить

Из корня проекта:

```powershell
dotnet build .\RasterRotation.sln
```

Запуск GUI:

```powershell
dotnet run --project .\src\RasterRotation.Wpf
```

Запуск GUI сразу с изображением:

```powershell
dotnet run --project .\src\RasterRotation.Wpf -- "C:\Images\photo.jpg"
```

Справка CLI:

```powershell
dotnet run --project .\src\RasterRotation.Cli -- --help
```

Информация о файле:

```powershell
dotnet run --project .\src\RasterRotation.Cli -- "C:\Images\photo.jpg" --info
```

Поворот и сохранение:

```powershell
dotnet run --project .\src\RasterRotation.Cli -- "C:\Images\photo.jpg" --rotate 90 --output "C:\Images\photo_rotated.jpg"
```

Проверка перед демонстрацией:

1. Собрать решение и убедиться, что ошибок и предупреждений нет.
2. Открыть PNG, JPEG и TIFF.
3. Проверить повороты `-90`, `+90`, `180`.
4. Проверить произвольный угол, например `12.5`.
5. Проверить оба отражения.
6. Выделить область мышью и выполнить обрезку.
7. Включить сетку.
8. Сохранить результат и открыть его повторно.
9. Перезапустить приложение и проверить сохранение темы и фона.
10. Выполнить хотя бы одну CLI-команду.

## 11. Короткий рассказ для защиты

Можно объяснить проект так:

> Решение состоит из трёх проектов. `RasterRotation.Core` — переиспользуемая библиотека с моделью изображения, интерфейсами загрузки и трансформации и их реализацией через Windows Imaging Component. `RasterRotation.Wpf` — графический интерфейс, который принимает действия пользователя и вызывает библиотеку. `RasterRotation.Cli` предоставляет те же операции через параметры командной строки. Точка входа GUI — обработчик `OnStartup` в `App.xaml.cs`, а точка входа консольной программы — метод `Main` в `Program.cs`. Для расширяемости применены интерфейсы, наследование операций, свойства, событие изменения документа и коллекция операций. Пользовательские настройки сериализуются в JSON в папку AppData.

Если спросят, почему логика вынесена в библиотеку:

> Чтобы алгоритмы не зависели от конкретного интерфейса. Одни и те же классы Core используются WPF-окном и консольной программой и могут быть подключены к WinForms или другому UI.

Если спросят, где реализован сам поворот:

> В `WicImageTransformer.cs`: прямые углы обрабатывает `RotateRightAngle`, а произвольный угол — `RotateFree`.

Если спросят, где реализована обрезка мышью:

> События мыши и перевод экранных координат находятся в `MainWindow.xaml.cs`, а фактическое создание обрезанного изображения — в методе `Crop` класса `WicImageTransformer`.

Если спросят про форматы:

> Загрузка и сохранение построены на WIC. Стандартные PNG, JPEG, TIFF, BMP, GIF и JPEG XR обрабатываются системными кодировщиками. Для HEIF или WebP требуется установленный в Windows WIC-кодек. Программа стремится сохранять исходный контейнер, но расширенные метаданные и анимация в текущей версии полностью не переносятся.
